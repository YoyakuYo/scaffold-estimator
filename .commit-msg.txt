feat(bim): phase 5 BIM Viewer - upload IFC and render in 3D in the browser

The third product is now usable end to end. IFC parsing happens
client-side via web-ifc; the existing ifc-loader and BIM material library
do all the heavy lifting (procedural brick walls, slate roofs, glass
curtain walls, concrete slabs, steel members) — the new pages just wire
them into a Three.js scene with OrbitControls.

Backend (gated behind @RequiresProduct('bim'))
- New BimModule + BimController:
    POST /bim/track-upload — records the upload into upload_events
    (kind 'ifc' | 'dxf' | 'bim_other') so the superadmin cockpit sees BIM
    activity. The raw file never leaves the user's machine.

Frontend
- /bim home page: locked overlay with /billing#bim CTA when not
  subscribed; otherwise shows an "Open viewer" card and a privacy note.
- /bim/viewer page: full Three.js scene (camera, lights, grid, OrbitControls)
  bootstrapped via dynamic `import('three')`. Drag-and-drop or pick an .ifc
  file → parseIfcToMeshes() → meshes added with createBimMaterialSet()
  and getMaterialForElement() so walls/slabs/roofs/glass/columns render with
  realistic PBR materials. Auto-frames the camera to the bounding box.
  Per-element-type counts shown after load (e.g. wall: 24, window: 18).
- lib/api/bim.ts client.
- ja/en/fr translations for the BIM landing + viewer.

Quality
- Backend tsc --noEmit: passes.
- Frontend tsc --noEmit: passes.

Deferred (real Phase 5 follow-up):
- DXF → procedural BIM extrusion (walls/slabs/windows/roof from layered
  2D DXF). Multi-week effort on its own; needs polygon detection +
  window/door grid generators that aren't trivial.
- Saved BIM model list (this milestone is single-shot view; uploads are
  audit-only, files are kept in browser memory).
