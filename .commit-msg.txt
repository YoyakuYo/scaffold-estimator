feat(construction-plan): gap #1 - persist uploaded files to Supabase Storage

Closes the file-storage gap from the Phase 3 audit. Construction Plan
uploads now actually save bytes (not just metadata), enabling downloads,
previews, and a future AI vision re-classification pass.

Migration
- 137_construction_plan_files_bucket.sql: creates the private
  `construction-plan-files` bucket and service-role / authenticated-read
  policies on storage.objects scoped to that bucket.

Backend
- StructuralTakeoffService.addFilesToSet() now:
  * Inserts the metadata row first (giving each file a stable id).
  * For every input that includes a Buffer, uploads
    `<setId>/<fileId>.<ext>` to the bucket and patches storage_path on
    the row. Storage failures are logged but never throw, so the user
    still keeps the classification rows.
- New StructuralTakeoffService.getFileSignedUrl() — 5-minute signed
  download URLs via Supabase Storage. 404s when the row is metadata-only.
- StructuralTakeoffService.deleteFile() now also removes the stored
  object (best-effort, logged on failure) so the bucket doesn't accumulate
  orphans.
- New endpoint GET /structural-takeoff/sets/:setId/files/:fileId/url
  (gated by @RequiresProduct('construction_plan')).
- Controller upload now passes Multer buffers through (was hard-coded to
  null in the foundation milestone).

Frontend
- structuralTakeoffApi.getFileSignedUrl().
- File rows on the set-review page show a Download icon for any row that
  has storage_path. Click opens the signed URL in a new tab; failures are
  silent (button just doesn't navigate). Metadata-only files still show
  Delete only.
- ja/en/fr translation key for "Download".

Quality
- Backend tsc --noEmit: passes.
- Frontend tsc --noEmit: passes.
- No lint errors.

Deployment note
- Apply supabase-migrations/137_construction_plan_files_bucket.sql before
  deploying. Until applied, uploads still record metadata correctly but
  the bucket insert silently fails (storage_path stays null and the
  Download button doesn't appear) — no data loss.
