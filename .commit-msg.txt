feat(construction-plan): gap #7 - foreman truck-assignment overrides + persistence

Foremen can now reassign truck types per delivery and have those edits
survive page reloads, schedule recomputes, and the Excel export. The
generated bin-pack stays the starting point; the override is the
contract.

Migration
- 139_delivery_plan_overrides.sql: new delivery_plan_overrides table
  (set_id PK + edits JSONB + updated_by + updated_at). Service-role only
  RLS.

Backend
- New schedule/delivery-plan-overrides.ts:
  applyDeliveryPlanOverrides(plan, overrides) swaps truck.truckType /
  truckLabel / payloadKg / bedLengthMm in-place per (date, binNo) edit
  and rebuilds the flat plan.trucks list so subsequent consumers see
  the override.
- StructuralTakeoffService gains getDeliveryOverrides() and
  saveDeliveryOverrides() — JSON-blob persistence with a 1000-truck cap
  + minimal validation.
- GET /sets/:setId/delivery-plan now applies overrides server-side and
  returns the original `overrides` payload alongside the plan so the
  UI can compute "dirty" state.
- New endpoints:
    GET /sets/:setId/delivery-plan/overrides
    POST /sets/:setId/delivery-plan/overrides
- Excel exporter accepts an `overrides` option; the controller passes
  the saved overrides through, so the workbook always matches what the
  foreman sees in the UI.

Frontend
- structuralTakeoffApi.getDeliveryOverrides + saveDeliveryOverrides.
- Schedule page truck-type column becomes a <select> bound to a local
  `overridesDraft` keyed by `date|binNo`. Changing a truck type updates
  the draft only — nothing hits the server until you click Save.
- New header strip on the delivery panel:
  * "unsaved changes" badge (only visible when draft != server).
  * Discard button — resets draft to the server overrides snapshot.
  * Save button — POSTs the draft, invalidates the query so the UI
    re-renders with overrides applied.
- ja/en/fr keys for the three new labels.

Quality
- Backend tsc --noEmit passes.
- Frontend tsc --noEmit passes.

Deployment
- Apply supabase-migrations/139_delivery_plan_overrides.sql before
  rollout. The column default of '{}' makes the table safe to leave
  empty: any project that never overrides truck assignments gets the
  generated plan as before.
