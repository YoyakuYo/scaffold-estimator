feat(construction-plan): gap #6 - title-block OCR re-classification

Beyond the deterministic filename heuristic, files can now be
re-classified by reading the title block of the actual drawing. This
unlocks classification for files with bad/generic names (a real-world
problem on construction sites where filenames are often "S001.pdf").

Backend
- New TitleBlockVisionService (extractors/title-block-vision.service.ts)
  built on the existing Anthropic SDK already wired in vision-bim.
  Single-shot Claude Vision call with a tight Japanese-aware system prompt:
  reads 伏図 / 柱リスト / 大梁リスト / 階段詳細 / EVシャフト / 階高表 from
  the title block; normalizes floor labels to 1F / RF / B1 / PH; returns
  block (A/B/C/D) and a confidence number. Defensive JSON parsing.
- StructuralTakeoffService.reclassifyFileFromContent():
  * Loads the file from the construction-plan-files bucket (gap #1
    enables this — required because vision needs the bytes, not just
    metadata).
  * For PDFs, rasterizes page 1 through Sharp at 200 DPI / max 2048 px
    (same recipe vision-bim already uses).
  * Sends to Claude, parses, patches the row with classification_source
    set to 'manual' so the result is sticky and can never be clobbered
    by a re-run of the filename classifier.
- New endpoint POST /structural-takeoff/sets/:setId/files/:fileId/reclassify-from-content
  (gated by @RequiresProduct('construction_plan'), throttled at 12/min).

Frontend
- structuralTakeoffApi.reclassifyFromContent().
- Set-review page: each file row that has a stored file now shows a
  violet Sparkles button next to Download and Delete. Click triggers
  the AI re-classification, the row's kind/level/block update inline
  on success.
- ja/en/fr key for the button.

Quality
- Backend tsc --noEmit passes.
- Frontend tsc --noEmit passes.

Operational notes
- Requires ANTHROPIC_API_KEY on the backend (already used by vision-bim).
- Optional ANTHROPIC_TITLE_BLOCK_MODEL env override; defaults to
  claude-3-5-haiku-20241022 since the prompt is tiny and we want this
  cheap.
- Files must have storage_path (i.e. uploaded after gap #1's storage
  migration). Pre-storage files just don't show the AI button.
