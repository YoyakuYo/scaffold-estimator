1 Cover letter

I ship a full-stack scaffold BOM app for construction: users define building perimeters, pick Kusabi (wedge-type) or frame rules, and get deterministic material lists with Excel export, 2D SVG, and Three.js 3D. The stack is Next.js + Tailwind on the client and NestJS on Node for APIs, auth, and persistence. I used AI tools heavily for velocity; calculation logic stays explicit and testable so estimates remain auditable. I’m comfortable owning features end-to-end, reviewing AI-generated code, and keeping architecture documented so the codebase stays consistent.

2 AI-built project (Node / Tailwind at scale)

Scaffold material estimator — monorepo with meaningful surface area: multi-step config UI (walls, spans, stairs, per-type rules), a pure TypeScript client engine for quantities, NestJS REST + TypeORM + PostgreSQL, JWT auth, PWA, i18n, vision/BIM-assisted footprint input, and exports. Tailwind is used throughout the Next.js app at real product scale (forms, dashboards, complex layouts). AI accelerated UI wiring, refactors, and boilerplate; domain rules and BOM math live in dedicated modules with clear contracts.

Note: Stack is Next.js + Node (NestJS), not Astro — same class of “modern full-stack + Tailwind.”

3 Unit testing in AI-first workflows

  • Isolate truth: Test pure calculators and serializers with fixed inputs/outputs so refactors don’t change business results silently.
  • Regression tests: When a bug appears, add a failing test first, then fix — AI refactors are less likely to reintroduce the same bug.
  • CI gates: Run unit tests, type-check, and lint on every change so generated code can’t skip the bar.
  • Coverage: Prioritize critical paths (money, auth, quantity rules) over blanket %; snapshots only for stable, reviewed outputs.

4 Subagents, MCP, orchestration

I use task-focused subagents for parallel work: e.g. one pass to map API usage, another to implement a feature, then merge with a single human review. That keeps context windows focused and reduces conflicting edits.

MCP where it fits: structured tool access (docs, payments, etc.) instead of pasting secrets into chat; treat integrations like any other dependency — schema-checked and reviewed.

Pattern: One thread owns architecture and file ownership; exploration runs read-only until the implementation plan is clear.

5 AI models & editors

Editor: Cursor (AI pair programming, repo-aware context).

Models: Claude for larger refactors and multi-file reasoning; GPT-4 class for quick iterations and vision-heavy flows where the product uses them; smaller/faster models for mechanical edits when quality is sufficient.

6 Quality control & architecture when AI writes most code

  • Repo docs: CLAUDE.md / cursor rules so AI stays inside agreed boundaries (e.g. engine vs pages).
  • Strict TypeScript + ESLint to catch sloppy generated code early.
  • Human review on auth, billing, and any path that affects quoted quantities.
  • Graceful degradation (e.g. optional AI features when API keys are missing).
  • Periodic trace: Walk one user journey through the stack to remove duplication and dead paths.
